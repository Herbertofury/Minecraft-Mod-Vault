# 🌱 WorldForge — Pruning, Retrogen & Forever Worlds

> **Status:** 📋 WorldForge roadmap.

WorldForge must support both **simple manual pruning** and advanced build-aware retrogen. The smart system can never make the simple workflow harder.

## Simple mode

**Select → Prune → let the chosen Minecraft version regenerate normally.**

Target selection tools:

- click/paint chunks;
- rectangle/box;
- circle/radius;
- polygon/lasso;
- freehand;
- line/corridor;
- coordinate ranges;
- add/subtract/intersect/invert/grow/shrink;
- per-dimension jobs;
- `Prune Selected` or `Prune Everything Except Selected`;
- `Prune Only` or `Prune + Regenerate/Test`.

Manual selection wins. Build-aware analysis is optional.

## Player-build-aware retrogen

Minecraft does not store a perfect “player placed this” bit. WorldForge therefore uses multiple evidence sources and confidence rather than pretending certainty.

Potential signals:

- differences from a reproducible source-version natural baseline;
- containers and inventories;
- block entities;
- signs/books;
- redstone;
- crafted/non-natural block palettes;
- farms/roads/mines/excavation;
- named entities/pets;
- portals, rails, maps and item frames;
- `InhabitedTime`, `LastUpdate`, `DataVersion` and generation status as supporting signals only.

> [!CAUTION]
> `InhabitedTime` is **not proof** that a chunk contains a player build, and a low value is not proof that a chunk is disposable. It is only one input to a confidence model. Explicit user protection always wins.

## Protect My Builds → Regenerate the Rest

1. determine per-chunk source version/history;
2. reconstruct old natural baseline where possible;
3. extract player/world-history delta;
4. generate target-version terrain using the real target generator;
5. preserve/reapply protected deltas transactionally;
6. repair lighting, heightmaps, POIs, structure refs, neighbor states, portals/maps/ticks;
7. seam-blend boundaries;
8. launch and inspect with TestGrid/Agent Driver.

## Layer-coherent pruning

Deleting a Java terrain chunk without accounting for its matching entity and POI records can leave a world internally inconsistent. WorldForge should treat the logical chunk as one operation across the relevant storage layers.

For Java this includes, as applicable:

- `region/r.x.z.mca` terrain/chunk data;
- `entities/r.x.z.mca` entity data;
- `poi/r.x.z.mca` POI data;
- related structure/portal/saved-data references that point into affected chunks.

For Bedrock, WorldForge should apply equivalent integrity rules across the relevant LevelDB key families rather than exposing raw key deletion as the normal user workflow.

This is one reason the new in-game **[Chunk Editor - MCA-Selector](https://modrinth.com/mod/mca-selector)** is useful research: its deletion workflow explicitly coordinates region, entity and POI layers.

## Quarantine-before-delete

Borrow the safer pattern exposed by tools such as **[ChunkCleaner](https://github.com/zeroBzeroT/ChunkCleaner)**: a pruning job should be able to move candidate data into a quarantine/snapshot set instead of immediately destroying it.

Recommended modes:

- preview only;
- export selected chunks;
- quarantine selected chunks;
- prune selected chunks;
- prune + regenerate;
- restore quarantine.

The operation journal should retain the original chunk coordinates, dimension, source file/key, hashes and selection reason so rollback is deterministic.

## Resumable pregeneration and maintenance

The current ecosystem shows that world operations are often long-running server jobs, not one-click desktop edits. **[Chunky](https://modrinth.com/plugin/chunky)** and **[Chunky Extension](https://modrinth.com/mod/chunky-extension)** are useful benchmarks for pregeneration and player-aware pause/resume behavior; **[Regionerator](https://github.com/Jikoo/Regionerator)** is a useful reference for gradual world maintenance rather than giant destructive sweeps.

WorldForge should therefore have a shared long-operation scheduler for:

- pregeneration;
- retrogen;
- pruning;
- conversion;
- map indexing/rendering;
- integrity scans;
- repair/rewrite jobs.

Scheduler requirements:

- persistent operation manifest;
- exact completed/pending region/chunk sets;
- interruption-safe resume;
- idempotent completed steps;
- user-configurable CPU/IO/memory pressure limits;
- pause while players are online, or throttle by player count/TPS/MSPT when integrated with a server;
- maintenance windows;
- explicit cancel with a consistent partial state;
- ETA/progress based on measured throughput, not fake percentage animation;
- post-job save/reopen/validation pass.

## Mixed-version / height-expansion repair

Special handling targets worlds stuck across major worldgen transitions (including classic pre-1.18 → 1.18+ depth/height metadata problems), so new lower terrain and blending are generated by the **real target Minecraft rules** instead of guessed filler.

Modern folder/schema transitions should also be treated as first-class migration problems rather than simple directory moves. **[WorldVersionBackport](https://modrinth.com/mod/worldversionbackport)** is a useful research case for how version-specific world-layout changes can complicate downgrade/backport workflows; WorldForge should solve these through explicit source/target adapters, backup-first planning and runtime verification.

## Inspection before regeneration

Before a large prune/retrogen job, WorldForge should provide an inspection layer inspired by **[MCA Selector](https://github.com/Querz/mcaselector)**, **[uNmINeD](https://unmined.net/)** and **[Seed Atlas](https://github.com/DUzzL/Seed-Atlas)**:

- 2D chunk map with LOD;
- dimension switcher;
- `DataVersion` heatmap;
- `LastUpdate` / age heatmap;
- `InhabitedTime` heatmap;
- parse/error overlay;
- player-build confidence overlay;
- protected/manual selections;
- source-vs-target terrain diff;
- seed biome/structure overlay where reproducible;
- proposed regeneration result preview when technically feasible.

## Forever World workflow

Protect history → diagnose and map → identify safe natural terrain → preview target worldgen → quarantine/prune → retrogen/pregenerate new features → compact/repair → real-game verify → checkpoint.
